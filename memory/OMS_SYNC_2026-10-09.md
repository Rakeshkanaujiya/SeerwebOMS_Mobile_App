# Web → Mobile comparison (2026-10-09)

Source inspected: `../client/src`, `../live_backend/app`, and current mobile working tree. Existing uncommitted work is preserved. Local source has not yet been proven identical to the deployed portal.

| Web feature/API | Current Mobile implementation | Missing/Different | Required Mobile change |
|---|---|---|---|
| Login / role permissions | Auth refresh, dealer/staff/retailer routes, permission services | Already implemented | Preserve and regression check |

| Barcode | Product attributes and backend search include barcode, item master supports barcode | No demonstrated camera scan workflow in inspected Web Create Order | Preserve text barcode search; do not invent scanner |

Android end-to-end and authenticated live API/order verification are required before release. Local debug builds may be used for verification. No release/Play Store build or publication is authorized. The user expressly requires approval before any real order submission.

## Changes made in this session

- `src/lib/cartPricing.ts`: parallel bounded lookup of only cart product IDs; server effective rates; unavailable-item validation; merge pricing/GST onto current quantities.
- `src/lib/useCartPricing.ts`: selected-party/ID state, cancellation of superseded requests, loading/error state and refocus retry. Editing existing orders retains agreed price/tax snapshots.
- `context/CartContext.tsx`: atomic REPRICE action without replacing quantities or variant/color identities.
- `screens/sales_executive/StaffScreen.tsx`: remove customer-switch clear, stable catalog endpoint across customer/order tabs, background cart repricing, remove undocumented 999-unit cap, status text while repricing.
- `screens/StaffCartScreen.tsx`, `screens/CartScreen.tsx`: separate account boot, GST lookup and cart hydration; refresh prices before totals/payload; block checkout during loading/errors; manual row quantity callback. Existing order edits retain snapshots and unavailable historical lines.
- `components/CartLineItem.tsx`: quantity input between minus/plus, positive whole numbers applied immediately, incomplete edits committed to one on blur (Web behavior).
- `components/ProductCart.tsx`: remove undocumented 999-unit cap.
- `components/BottomTabNavigator.tsx`: restrict tab routes to the actual tabs, fixing navigation typecheck without a runtime routing change.
- `tsconfig.json`: TypeScript 5.x-compatible ignoreDeprecations value.
- `.verification/cart-pricing.test.cjs`, `.verification/live-oms-parity.cjs`: unit/race tests and read-only authenticated live probes; no persisted tokens/passwords and no order POST/PUT.
- This comparison/report. Generated verification bundles, UI captures and summary JSON are under `.verification`.

No Web source, backend source, Tally Bridge or Ecom2Tally files have been modified in this session. Existing uncommitted changes in those projects predate this work.

## Unresolved / release gates

- `/cart-settings` returns HTTP 500 for both dealers: `Cart settings migration is required`. The existing backward-compatible migration is `../live_backend/app/Database/Migrations/2026-09-26-000001_CreateCartSettings.php`. It has not been deployed or run here. Full cart-settings synchronization cannot be certified until this server issue is resolved; mobile retains its existing cache/default fallback.
- Full Android quantity/customer-change/cart/review flow for both roles remains to be completed after native runtime recovery.
- No real order has been submitted. Server persistence and order visibility remain unverified pending the user's explicit approval of a concrete test order.
- Garment color and size-set prices are deliberately preserved by the new refresh service. Customer-specific garment set repricing requires an agreed Web rule; single-unit effective rates cannot safely overwrite set totals.
- No camera barcode scanner was added: text search and existing barcode attributes are retained. Full desktop settings/admin editors are outside this focused ordering synchronization.
- Expo dependency check in the network-enabled dev server recommends patch updates to Expo 54.0.37 and expo-constants 18.0.14; installed versions remain 54.0.35 / 18.0.13. No automatic dependency upgrade was made during the parity work.
